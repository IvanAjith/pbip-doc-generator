Disclaimer

Not 100% working yet. Use the output as a first draft.

The tool has been tested on the Standex report and on made-up inventory, streaming, HR and gaming reports. Reports differ a lot, and every new PBIP can show a pattern it does not handle yet. It follows fixed pattern rules, a built-in glossary of 177 terms and, if you choose, an AI, so it gets better as it is tested on more files. AI mode has been tested with simulated replies and still needs a live check with a company-issued key. Until then, a person must review every output before anyone relies on it.

Data storage modes: what works today

The pages, visuals, filters, colours, DAX explanations and glossary do not depend on how the data is stored. They come from the report and measure definitions, never from the data itself. Only the data-source details differ.

Import modeWorks

Tested. The source of each table (database, schema, view or file) is read from its definition and listed in the manual and the HTML.

DirectQueryExpected to work

It uses the same source definitions as Import, so sources should be read as usual. Not yet tested on a real DirectQuery report.

Direct Lake (Microsoft Fabric)Work in progress

The three documents are produced, and pages, measures and glossary entries all work. The Lakehouse or Warehouse behind each table is not read yet, so the Data Sources section lists the tables without their source.

Storage mode of each tableWork in progress

The documents do not yet say whether a table is Import, DirectQuery or Direct Lake.

Report-only project (live connection to a published model)Not supported yet

The tool needs the .Report and .SemanticModel folders side by side, and stops with a message if the model is missing. Workaround: also get the model's project folder, for example through Fabric Git integration, and put both in source/.

    Decisions to agree with leadership

    Suggestions, not rules.

    • Who and what. Which client projects the tool may run on, and who may run it.
    • AI and keys. Whether AI mode may be used on client projects, which AI services are approved, and who issues the keys.
    • Where the tool lives. The code sits in a private repository on a personal GitHub account today. Agree whether it moves to a company repository, and who gets access.
    • Where outputs live. Where the files are stored and who can open them.
    • Sign-off. Who reviews the documents before they reach a client.
    • More test files. How extra PBIP files are collected for testing, with the owner's permission, so coverage grows safely.
